# 해성호의 마지막 기록

RAG와 Tool Calling을 활용해 만든 텍스트 기반 추리게임입니다.

사용자는 크루즈에서 발생한 사망사건을 조사하는 탐정이 되어  
관계자를 인터뷰하고 사건 기록을 확인하며 범인을 추리합니다.

## 프로젝트를 시작한 이유

처음에는 RAG를 활용해 사건 문서를 검색하고 답변하는 간단한 프로젝트로 시작했습니다.

구현을 진행하면서 일반적인 RAG 구조를 추리게임에 그대로 사용하면  
아직 조사하지 않은 정보나 범인과 관련된 내용까지 검색될 수 있다는 문제가 있었습니다.

그래서 단순히 문서를 검색하는 챗봇이 아니라,  
플레이어의 조사 결과에 따라 새로운 문서가 해금되는 게임 구조로 발전시키고 있습니다.

## 현재 구현한 기능

- 사건 문서를 기반으로 답변하는 RAG
- Tool Calling을 활용한 인터뷰·감식·포렌식 조사
- 조사 결과에 따른 문서 해금
- 플레이어별 조사 상태 분리
- 현재 확보한 문서만 검색할 수 있는 권한 필터
- 조사현황 사이드바
- 최대 3회까지 사용할 수 있는 힌트
- 조사 진행도에 따른 6장 스토리 구성
- 충분한 조사를 완료하기 전까지 최종 지목 제한
- RAG 문서의 누락과 정답 누설을 확인하는 검사 스크립트

## 게임 진행

게임은 다음 6개의 장으로 진행됩니다.

1. 객실에 남은 흔적
2. 네 사람의 진술
3. 존재하지 않는 21시 15분
4. 객실 밖의 76분
5. 8년 전의 침묵
6. 마지막 기록

질문을 많이 한다고 다음 장으로 넘어가지는 않습니다.  
각 장에서 필요한 핵심 조사를 완료해야 다음 단계가 열립니다.

## 만들면서 해결한 문제

### 모든 문서가 처음부터 검색되는 문제

처음에는 Vector DB에 저장된 문서가 모두 검색 후보가 될 수 있었습니다.

추리게임에서는 아직 발견하지 않은 증거가 답변에 포함되면  
게임의 진행 순서와 추리 과정이 무너질 수 있었습니다.

이를 해결하기 위해 문서를 다음과 같이 분리했습니다.

```text
data/
├─ available/  # 게임 시작부터 검색할 수 있는 문서
└─ locked/     # 조사를 완료한 뒤 검색할 수 있는 문서
```

플레이어가 조사를 완료하면 해당 문서가 해금되고,  
현재 플레이어에게 허용된 문서만 RAG 검색 결과에 포함됩니다.

### 플레이어의 조사 상태가 공유되는 문제

기존 구조에서는 여러 사용자가 같은 조사 상태를 공유할 가능성이 있었습니다.

Streamlit의 세션 상태를 사용해 다음 정보를 플레이어별로 분리했습니다.

- 완료한 조사
- 해금된 문서
- 조사 기록
- 힌트 사용 횟수
- 현재 스토리 장

### 조사현황이 힌트가 되는 문제

처음에는 조사해야 할 전체 목록을 보여주는 방식을 고려했습니다.

하지만 전체 목록 자체가 정답을 알려주는 힌트가 될 수 있어,  
현재는 구체적인 미완료 목록 대신 조사 분야와 최근 기록만 사이드바에 표시합니다.

### RAG 토큰 사용 문제

Vector DB에서는 관련 문서를 넓게 검색하되,  
권한 필터를 통과한 후보 중 최대 12개만 재정렬에 사용합니다.

최종 답변에는 최대 3개의 문서 조각만 전달하여  
불필요한 토큰 사용과 관련 없는 정보의 유입을 줄였습니다.

## 사용 기술

- Python
- Streamlit
- OpenAI API
- LangChain
- ChromaDB
- Git / GitHub

## 프로젝트 구조

```text
app.py
  Streamlit 화면과 사용자 입력 처리

game.py
  Tool Calling, RAG 검색, LLM 답변 및 최종 판정

game_state.py
  조사 상태, 문서 해금, 장 진행 및 힌트 관리

build_vector_db.py
  최초 공개 문서의 Vector DB 생성

unlock_manager.py
  조사 완료 후 잠긴 문서 해금

validate_rag_documents.py
  문서 누락과 설정 누설 검사

data/available
  게임 시작 시 공개되는 사건 문서

data/locked
  조사 완료 후 해금되는 사건 문서
```

## 실행 방법

### 1. 패키지 설치

```bash
pip install -r requirements.txt
```

### 2. 환경변수 설정

프로젝트 폴더에 `.env` 파일을 만들고 OpenAI API 키를 입력합니다.

```env
OPENAI_API_KEY=your_api_key
```

### 3. Vector DB 생성

```bash
python build_vector_db.py
```

### 4. 게임 실행

```bash
streamlit run app.py
```

### 5. RAG 문서 검사

```bash
python validate_rag_documents.py
```

## 개발 과정

이 프로젝트는 한 번에 현재 형태로 만들어진 것이 아닙니다.

```text
기본 RAG 질의응답
→ Tool Calling 기반 조사
→ 조사에 따른 문서 해금
→ 플레이어별 상태 분리
→ 사이드바와 힌트 추가
→ 사건 설정과 시간선 정리
→ 6장 진행 시스템
→ 장별 조사 제한
→ RAG 문서 자동검사
```

현재 `main` 브랜치에는 초기 프로토타입을 유지하고,  
`develop` 브랜치에서 기능을 개선하고 있습니다.
